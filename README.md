# Parallel

SwiftUI-застосунок для macOS, який запускає кілька незалежних екземплярів одного застосунку, кожен зі своїм профілем даних.

## Збирання

Потрібні macOS 14+ і Swift 5.10+ (Command Line Tools достатньо, повний Xcode не обов'язковий).

```bash
./build.sh               # → build/Parallel.app (універсальний: Apple Silicon + Intel)
./build.sh --install     # ще й копіює в /Applications
./scripts/make-dmg.sh    # → build/Parallel-<версія>.dmg
```

Universal-бінарник збирається окремо для `arm64` і `x86_64` та склеюється через `lipo`, тому Xcode не потрібен.

### Встановлення з DMG на іншому Mac

Застосунок підписаний ad-hoc, без Developer ID і нотаризації, тому під час першого запуску завантаженого DMG macOS попередить про неперевіреного розробника. Відкрийте його так: клацніть правою кнопкою на `Parallel.app` → **Відкрити**. На macOS 15+ замість цього: **Системні параметри → Конфіденційність і безпека → «Все одно відкрити»**. Або зніміть карантин:

```bash
xattr -dr com.apple.quarantine /Applications/Parallel.app
```

## Як користуватися

1. Натисніть **+** (або ⌘O) чи перетягніть `.app` у вікно.
2. Для кожного застосунку створіть потрібну кількість профілів.
3. **Запустити**: стартує окремий екземпляр із даними цього профілю. **Запустити всі** запускає всі профілі.

У кожного профілю є поле для додаткових аргументів командного рядка (з підтримкою лапок).

## Способи ізоляції

| Режим | Для чого | Як працює |
|---|---|---|
| Автоматично | за замовчуванням | вибирає один із режимів нижче за вмістом `.app` |
| Electron / Chromium | Slack, Discord, VS Code, Chrome, Brave, Edge… | `--user-data-dir=<профіль>/data` |
| Firefox | Firefox, Zen, Waterfox | `-no-remote -profile <профіль>/firefox` |
| Клон застосунку | нативні застосунки | копія `.app` з bundle ID `<id>.parallel.<профіль>`, ad-hoc підпис |
| Без ізоляції | просто ще одне вікно-процес | `open -n`, дані спільні |

Усі дані зберігаються в `~/Library/Application Support/Parallel/`:
- `apps.json`: список застосунків і профілів;
- `Profiles/<UUID>/`: дані профілю або клон `.app`.

### Обмеження режиму «Клон»

- Клон створюється під час першого запуску і перестворюється автоматично, коли оригінал оновився або профіль перейменовано.
- Налаштування клону лягають у `~/Library/Preferences/<новий-id>.plist` / `~/Library/Containers/<новий-id>`. Застосунки, які зберігають дані в папці з фіксованою назвою (а не за bundle ID), можуть ділити ці дані з оригіналом.
- Застосунки з iCloud, Keychain-групами, push-сповіщеннями або перевіркою ліцензії App Store у клоні можуть працювати некоректно, бо ad-hoc підпис прибирає entitlements.
- Автооновлення (Sparkle) у клоні вимкнено. Оновлюйте оригінал, і клон перестворюється сам.
